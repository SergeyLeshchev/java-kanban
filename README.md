Task Manager — это бэкенд-приложение для управления задачами (задачами, эпиками и подзадачами) с REST API, историей просмотров и приоритизацией по времени. 
Backend-приложение с HTTP API для управления задачами, реализованное на чистой Java без фреймворков для глубокого понимания основ.
--------------------------
Язык: Java
Веб-сервер: com.sun.net.httpserver (встроенный HTTP Server)
Сериализация: GSON
Тестирование: JUnit
Контроль версий: Git
---------------------------
CRUD-операции для трех типов сущностей:
Task (Задача) — базовая единица работы.
Epic (Эпик) — крупная задача, состоящая из 
Subtask (Подзадача).
Расчет статуса Эпика автоматически на основе статусов его подзадач.
Временные интервалы: Каждая задача имеет время начала, продолжительность и дедлайн. Реализована валидация на отсутствие пересечений по времени.
Приоритизированный список: Получение всех задач, отсортированных по времени начала.
История просмотров: Последние 10 просмотренных задач (реализация через кастомный HistoryManager).
Полноценное REST API с обработкой HTTP-кодов состояния (200, 201, 404, 406, 500).
----------------------------
Интерфейс TaskManager — определяет контракт для менеджера задач. Позволяет в будущем легко подменить реализацию (например, на FileBackedTaskManager).
Класс InMemoryTaskManager — основная реализация логики:
Хранение данных в HashMap для быстрого доступа по ID.
Использование структуры данных созданной из двусвязного списка и HashMap для истории со сложностью алгоритма O(1).
Алгоритм проверки пересечений задач isTaskCross() гарантирует, что задачи не перекрываются по времени.
Автоматический пересчет статуса и времени эпика при изменении его подзадач.
История просмотров: Реализована через отдельный интерфейс HistoryManager (паттерн Strategy). В данном случае используется InMemoryHistoryManager, хранящий историю в LinkedList с ограничением в 10 элементов.
Обработка ошибок: Использованы кастомные исключения (NotFoundException, HasInteractionsException) для чистоты кода и понятной обработки на уровне API.
Слой HTTP-обработчиков:
Абстрактный BaseHttpHandler выносит общую логику (парсинг ID, отправка ответа).
Наследники (TaskHttpHandler, EpicHttpHandler, SubtaskHttpHandler) обрабатывают специфичные для сущности эндпоинты.
Логика определения эндпоинта (getEndpoint) на основе метода и пути запроса.
